# Instrumentation-based PGO
![[屏幕截图_20261015_151555.png]]
Abstract: Profile-guided optimization (PGO) is an important component in modern compilers. By allowing the compiler to leverage the program's dynamic behavior, it can often generate substantially faster binaries. Sampling-based profiling is the state-of-the-art technique for collecting execution profiles in data-center environments. However, the lowered profile accuracy caused by sampling fully optimized binary often hurts the benefits of PGO; thus, an important problem is to overcome the inaccuracy in a profile after it is collected. In this paper we tackle the problem, which is also known as profile inference and profile rectification. We investigate the classical approach for profile inference, based on computing minimum-cost maximum flows in a control-flow graph, and develop an extended model capturing the desired properties of real-world profiles. Next we provide a solid theoretical foundation of the corresponding optimization problem by studying its algorithmic aspects. We then describe a new efficient algorithm for the problem along with its implementation in an open-source compiler. An extensive evaluation of the algorithm and existing profile inference techniques on a variety of applications, including Facebook production workloads and SPEC CPU benchmarks, indicates that the new method outperforms its competitors by significantly improving the accuracy of profile data and the performance of generated binaries
摘要：性能剖析引导优化（Profile-Guided Optimization，PGO）是现代编译器的重要组成部分。通过让编译器利用程序的动态行为，它通常能够生成性能显著更快的二进制文件。基于采样的性能剖析是数据中心环境中收集执行剖析信息的最先进技术。然而，对完全优化后的二进制文件进行采样会导致剖析信息精度降低，这常常损害 PGO 的收益；因此，一个重要问题是在收集到剖析信息后克服其不准确性。本文研究该问题，它也被称为剖析推断和剖析校正。我们研究了经典的剖析推断方法——基于在控制流图中计算最小费用最大流——并开发了一个扩展模型，以刻画真实世界剖析信息所期望的性质。接下来，我们通过研究相应优化问题的算法层面，为其提供坚实的理论基础。然后，我们描述了一种新的高效算法及其在开源编译器中的实现。在包括 Facebook 生产工作负载和 SPEC CPU 基准测试在内的多种应用上，对该算法与现有剖析推断技术进行的广泛评估表明，新方法显著提高了剖析数据的准确性以及所生成二进制文件的性能，从而优于其竞争者。
## 一、 核心原理：工业界主流编译器如何做“精确插桩”？

插桩式反馈编译优化（Instrumentation-based Profile-Guided Optimization, PGO / FDO）通过“插桩构建（`-fprofile-generate`） $\to$ 业务负载训练（Train） $\to$ 反馈重编（`-fprofile-use`）”的两阶段闭环，获取程序 100% 精确（Exact）的运行期频次信息。其底层实现建立在三大核心机制之上：

### 1. 探针位置消减：基尔霍夫流守恒与最大生成树算法
现代编译器（GCC、LLVM）并不会在每个基本块（Basic Block）或每条控制流边（CFG Edge）上无脑插入计数器，而是采用 **Ball-Larus 最优边插桩算法** **[Ball & Larus, TOPLAS'94]**：
* **流守恒数学基础（Flow Conservation）**：在强连通控制流图 $G = (V, E)$ 中，任意节点 $v \in V$ 满足基尔霍夫第一定律（流入边执行频次之和恒等于流出边执行频次之和）：
  $$\sum_{u \to v \in E} \text{Count}(u \to v) = \sum_{v \to w \in E} \text{Count}(v \to w)$$
* **最大生成树（Maximum Spanning Tree, MST）探针放置**：
  1. 包含 $|V|$ 个顶点、$|E|$ 条边的控制流图存在 $|V|-1$ 个线性无关的流守恒方程。只需构造一棵生成树 $T$，**仅对不在生成树上的 $|E| - |V| + 1$ 条“弦边”（Chords, $E \setminus T$）插入探针**，其余树边（Tree Edges）频次即可在离线阶段通过后序深度优先遍历（Post-order DFS）在 $O(|E|)$ 时间内 100% 唯一还原 **[Ball & Larus, TOPLAS'94]**。
  2. **热边避让策略**：编译期先通过静态启发式估算各边权重，利用 Kruskal 算法求解**最大生成树**——使高频执行的**循环内部热边进入生成树 $T$（零插桩指令）**，而将低频执行的**冷边/异常出口作为弦边 $E \setminus T$（放置探针）**，在 SPEC 测试集上可减少 50% 的静态探针数与 67% 的动态计数指令执行量 **[Ball & Larus, TOPLAS'94]**。
  3. **关键边拆分（Critical Edge Splitting）**：若需插桩的弦边 $u \to v$ 满足“$u$ 有多个后继且 $v$ 有多个前驱”，编译器必须在 $u$ 与 $v$ 之间新建一个空的中间跳转块（Split BB）专门挂载计数指令 **[Ball & Larus, TOPLAS'94]**。
* **向路径级插桩的演进**：若需进一步区分菱形控制流的不同上下文路径，可将 DAG 中的每条无环路径编码为唯一整数和（Path Sum）并在寄存器中累加状态，但会引入约 30% 的平均运行开销 **[Ball & Larus, MICRO'96]**。

### 2. 数值插桩（Value Profiling）
仅采集控制流边频次无法解决 C/C++ 中**虚函数/函数指针调用（Indirect Call）无法内联**以及**动态长度内存操作无法特化**的痛点。主流编译器通过注入数值探针（如 LLVM 的 `llvm.instrprof.value.profile`）捕获运行期**半不变量（Semi-invariant Variables）** **[Calder et al., MICRO'97]**：
* **Top-N-Value (TNV) 运行时表**：在调用点维护固定槽位数的频次表（划分稳定区 Steady Part 与暂存区 Clear Part 以过滤低频噪声），统计运行期出现频次最高的 $N$ 个具体数值或目标函数地址 **[Calder et al., MICRO'97]**。
* **指导关键优化**：
  * **间接调用提升**（Indirect Call Promotion, ICP）：若某虚函数或函数指针调用点的 Top-1 目标占比极高，二次编译时将其脱糖为条件直调（`if (fptr == &HotFunc) HotFunc(); else (*fptr)();`），从而打通跨模块函数内联 **[Calder et al., MICRO'97]**。

### 3. 工业界架构实现（以 LLVM IR-level PGO 为例）
* **Pre-inliner（插桩前预内联）**：现代 LLVM 弃用了早期的 Clang AST 前端插桩，将插桩推迟到中端 IR 早期（`PGOInstrumentationGen` Pass）。在插桩前先执行一轮启发式预内联与 CFG 简化，消除大量短小函数（如 C++ `getter/setter`），大幅缩减探针基数。
* **CFG 指纹对齐（`FuncHash`）**：对函数 CFG 拓扑结构计算 64 位哈希存入二进制 `__llvm_prf_data` 段；第二阶段 `-fprofile-use` 在完全相同的 IR 阶段校验哈希并挂载 `!prof` 分支权重元数据，实现**采集点与优化消费点的零偏差对齐**。
* **流水线元数据保真传播**：当后续优化 Pass 执行代码变换（如指令消除、替换或循环变换）修改 IR 控制流结构后，需通过形式化传播规则（如 Hydra 框架）动态更新挂载在 IR 上的 Profile 权重，防止分支概率元数据在优化流水线中失真（Profile Staleness） **[Fröhlich et al., OOPSLA'26]**。

## 二、 为什么插桩式 PGO 在终端复杂业务中难以推广？

尽管拥有生成树消减与预内联优化，插桩式 PGO 仍面临严重的工程与性能瓶颈：

| 瓶颈维度                                             | 底层机理与体系结构根源                                                                                                                 | 对终端实际业务的影响                                                        |
| :----------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------- |
| **1. 多线程缓存一致性风暴**<br>*(Cache Line Bouncing)*     | 全局边计数器紧凑排列在二进制 `__llvm_prf_cnts` 连续数组段中。多线程高并发下，非原子更新会因数据竞争丢失计数；若开启原子更新（`-fprofile-update=atomic`），多核高频争抢同一 64B Cache Line。 | 渲染服务等高并发多线程程序的运行吞吐量暴跌 **3～10 倍**。                                 |
| **2. 强实时业务时序问题**<br>*(Heisenbug / 数据失真)*         | 插桩指令与 Value Profile 运行时哈希表更新拖慢单帧执行时间，打破 60Hz/120Hz 渲染的强实时阈值（16.6ms / 8.3ms）。                                                | 触发**丢帧补偿、超时降级或锁竞争回退分支**，导致采集到的 Profile 实际反映的是“卡顿异常路径”而非正常业务路径。    |
| **3. 探针与构建流程开销**<br>*(Instrumentation Overhead)* | 拆分关键边破坏指令缓存（I-Cache）局部性并增加寄存器分配压力；细粒度路径记录与哈希校验本身亦存在显著固定开销 **[Wang et al., TDSC'26]**[cite: 1, 13, 14]。                      | 侵入式两阶段编译拉长大型仓库 CI/CD 构建周期 **[Shen et al., ASPLOS'23]**，开发者使用门槛极高。 |

## 三、 如何兼顾“低开销”与“高精度”？

围绕“削减插桩开销”与“弥合采样信息缺失”，学术界与工业界演进出三条可直接写入论文 Related Work 与 Motivation 的技术路线：

### 路线 1：编译期双路径复制与动态采样切换
* **代表工作**：**Arnold-Ryder 框架 [Arnold & Ryder, PLDI'01]**。
* **核心思想**：在编译期对函数或循环体进行代码复制（Code Duplication），同时生成一份**无插桩的快速路径（Fast Path）**和一份**带完整探针的慢速路径（Instrumented Slow Path）**。在函数入口与循环回边处仅维护一个轻量级采样计数器，绝大部分时间在无插桩的 Fast Path 上全速运行，仅按固定周期短暂切入 Slow Path 收集精确的上下文与边频次，将插桩开销降低一个数量级 **[Arnold & Ryder, PLDI'01]**。
本质：周期性采样
复杂点：OSR（栈上替换）。对齐所有寄存器、局部变量。然后才能切换PC指针

### 路线 2：复用程序原有仿射变量彻底消除循环探针（赛题指定文献 [3]）
* **代表工作**：**Nisse 框架 [Frénot & Pereira, CC'24 (赛题文献 3)]**。
* **核心思想**：传统 Ball-Larus 算法仍需在每个循环内保留至少一条弦边插入人工计数器（Artificial Counter）。Nisse 分析可归约循环（Reducible Loop）Header 块的 $\phi$ 节点及其在数据依赖图上的单入口单出口（SESE）环路：若程序原本的循环归纳变量或累加器满足仿射递增关系 $v_i = u_i + c_i$，则**直接删掉循环内的插桩探针**，仅在循环退出块（Exit Block）通过代数公式 $\text{Count} = (v_{\text{exit}} - v_{\text{init}}) / \text{step}$ 精确算出边执行次数，在保证 100% 精度下将 LLVM 测试集的平均插桩开销从 **26% 降至 13.8%** **[Frénot & Pereira, CC'24 (赛题文献 3)]**。

针对$$v_{exit}​=v_{init}​+step×Count$$（比如i++,ptr+=4）这类代码，减少插桩数量
### 路线 3：将插桩的“流守恒模型”迁移至硬件采样与后链接优化（核心切入点）
为了彻底免除线上插桩运行开销，最新工业界方案使用硬件 PMU（如 Intel LBR 或 ARM64 BRBE/SPE）进行零侵入采样，并借用插桩式 PGO 的图论模型修复采样失真：
1. **基于最小费用流的控制流频次重建（`profi` 算法）**：针对硬件采样数据残缺、有噪且违背流守恒的问题，将控制流图上的频次恢复形式化为**最小费用最大流（Min-Cost Maximum Flow）**问题，在贴合采样观测值的同时强行恢复与插桩式 PGO 相同的基尔霍夫流守恒约束，精准还原循环运行次数与冷热分支概率 **[He et al., POPL'22 (CCF-A, 赛题文献 1)]**。
2. **伪插桩映射与全程序重链接优化**：考虑到中端 IR 级插桩/采样与最终后端生成的二进制机器码之间仍存在结构差异 **[Panchenko et al., CGO'19 (赛题文献 2)]**，可通过在编译器中植入不生成真实指令的元数据锚点（如基本块段 Basic Block Sections 或伪探针），配合硬件采样在重链接阶段完成高精度的函数内联与基本块重排 **[Shen et al., ASPLOS'23]**。

ARM SPE、Intel LBR 这类硬件采样，不是精确计数器。采样有：

- 随机抽样误差；
    
- 指令乱序执行；
    
- 采样中断延迟（Skid）；
    
- 编译器内联后信息丢失。
    

所以映射回 CFG 的数据往往**不守恒**。

目标:找到一组修复后的频次：f(BB0), f(BB1), f(BB2), f(BB3)f(BB0​), f(BB1​), f(BB2​), f(BB3​)
使得：
1. **严格满足流守恒**：f(BB0)=f(BB1)+f(BB2)=f(BB3)f(BB0​)=f(BB1​)+f(BB2​)=f(BB3​)
2. **离采样观测值尽可能近**：修改代价最小。
