# 决策风险最小实现与本轮结果

LLVM 是本项目使用的编译器基础设施；profi 是 LLVM 已有的执行频次推断算法；DRAPER 是老师提出的决策风险感知恢复方案名称。本文用“重采样”表示反复模拟观测并重新求解，用“投影”表示在流约束和修改预算内调整计数。

## 本轮交付

已实现可运行的决策风险修正器、实际执行的预算选点，以及较大的标准套件数据集。32 项代码测试通过。最终同一份核心代码在 6 个 Embench 开发程序及 spiff 上完成编译、正确性检查和 15 轮交错计时。

**性能目标仍未达到。** 最终结果中 qrduino、nettle-aes、picojpeg 仍出现“计数误差降低，运行时间变差”。本轮把这类问题变成了可以按决策、修改量和实际时间检查的结果，尚未找到能普遍消除它们的代价模型。

## 实现了什么

| 老师方案中的内容 | 本轮代码与实际行为 |
|---|---|
| 流约束和不确定性 | 保留控制流、封闭内部调用、非负约束；每次重采样求解均保留实测校准计数 |
| 编译器决策 | 导出实际分支判断、基本块相对频率、内联成本和阈值；读取优化过程中的内联记录及机器块排列 |
| 决策损失 | 用重采样中的决策比例估计不确定性，乘以执行频次及静态指令数估计错误代价 |
| 有界修改 | 用线性规划降低决策裕量损失；总绝对改变量不超过校准计数总量的 1%；保留流约束、实测计数及非负约束 |
| 编译验收 | 重新编译候选；实际回放的风险必须降低，且所有可对应的稳定决策必须保持，否则输出校准结果 |
| 预算插桩 | 每程序最多 3 点、每函数最多 2 点、每循环最多 1 点；以重采样计数的上分位数估计更新成本，在预计总更新量 1% 内选点，再实际编译执行、读取计数并重新求解 |
| 输出 | 保存频次、重采样区间、分支风险标签、四类决策、修改预算、候选接受理由与实测插桩开销 |
| 变换来源证据 | 从伪探针建立优化前后来源关系，保留唯一/不明确来源、跨函数来源、多目的位置和缺失记录 |

预算选点遇到分支风险时，测量对应边的计数位置，避免只重复测分支入口。旧图缺少循环头编号时，同一函数内的循环共用一个限额；新导出的图包含循环头。

当前选点排序按决策所在块的频次归一化风险收益，实际预算则按待插桩位置的重采样计数上分位数扣除。这是启发式选点，还没有求解全局最优的插桩集合。

最终 7 项实验的实测插桩更新量均未超过选择时的预算。这个预算使用计数预测控制更新次数；1% 不是运行时间开销的保证。计数修正的 1% 上限则是求解器的显式约束，最终输出另做检查。

代码入口：`run_core_risk.py`；风险模型与预算：`draper/decision_risk.py`；编译器接口：`draper/llvm_bridge.cpp`；变换证据：`draper/evidence.py`；结果审计：`audit_core_results.py`。

## 风险目标怎样计算

对某个编译决策，令 `p` 为重采样中选择“是”的比例，`w` 为静态估计的错误代价。候选选择“是”时损失为 `w × (1 − p)`，选择“否”时为 `w × p`。把各决策的损失相加，再在修改预算内求候选。

不连续的决策先用局部线性模型与裕量损失近似；候选必须经过实际编译回放检查。因此，“线性规划目标下降”和“最终候选接受”分别记录。运行时间在输出固定后测量，没有用候选计时来选择本轮最终版本。

当前四类决策的具体范围：

- 分支：读取编译器是否将边概率判定为超过 80%。
- 基本块频率：读取实际频率，但风险划分使用“相对函数入口超过 10 倍”的研究阈值；它不等同于编译器全局冷热分区阈值。
- 内联：读取实际成本、阈值和优化事件；仅使用能唯一对应的调用位置，重复或缺失的事件不硬配对。用调用块与入口频次拟合局部敏感度，拟合差的记录不参与投影。
- 布局：以局部后继流量差近似，使用实际机器块排列核对。仅保留能够对应回早期基本块的局部次序。

本轮实际进入风险模型的内联决策在 picojpeg 与 spiff 中各有 2 个。其他程序虽然导出了内联结果，重采样中没有满足当前筛选条件的不稳定内联决策。

## 最终实验结果

最终目录：

- `/data/chaoni/chengli/draper-node3/data/core-risk-v4`
- `/data/chaoni/chengli/draper-node3/data/large-core-v2`

工具链为 Clang/LLVM 23.1.4。固定随机种子 42，模拟采样率 1/64，随机缺失比例 15%，20 次重采样。计时固定在允许使用的一个处理器上，版本交错运行 15 轮。表中正值表示相对 profi 加速，负值表示变慢；区间为配对时间比的重采样 95% 区间。

|---|---:|---:|---:|---|
| crc32 | 1.92% | 1.17% | +0.36% | −0.002% ～ +1.05% |
| slre | 7.46% | 4.31% | +3.60% | +2.64% ～ +4.58% |
| qrduino | 9.31% | 5.14% | −7.32% | −10.45% ～ −5.38% |
| nettle-aes | 5.68% | 5.00% | −0.29% | −0.41% ～ −0.19% |
| picojpeg | 5.57% | 4.23% | −8.30% | −8.92% ～ −7.81% |
| wikisort | 22.17% | 22.24% | +52.85% | +51.21% ～ +54.46% |
| spiff | 0.326% | 0.287% | −0.81% | −2.70% ～ +0.72% |

计数相对误差为所有基本块绝对误差之和除以参考计数之和。

spiff 使用上游的 `Sample.3` 与 `Sample.4` 文件，每轮启动新进程并保留正常参数；其余六项使用原有进程内重复入口计时。两种计时方法分别记录，不把七个程序直接合成官方套件分数。

**最终只有 nettle-aes 接受了额外风险投影，绝对修改量为 296.21，预算为 1,375.91。** 其他六项输出校准后的恢复结果。wikisort 和 slre 的收益不能归因于额外风险投影。候选被拒绝时，校准版本和最终版本的中间表示相同，两份计时之间的差值属于重复测量波动。

所有最终输出均通过非负性、修改预算、实测点和流残差审计。实测点最大绝对误差约为 `1.2 × 10^-13`。spiff 的最大控制流绝对残差约为 0.0053 次，属于浮点求解误差，审计文件保留绝对值。

## 从反例得到的结论

1. 静态指令数与执行次数还不能准确表示一个编译决策变错的运行时间代价。nettle-aes 通过了风险与稳定性检查，最终仍比 profi 慢约 0.29%。
2. 稳定决策保护偏保守。在同输入开发试验中，更早的候选曾让 qrduino 明显加速；最终规则因一个稳定决策发生变化而拒绝候选，留下较慢的校准版本。不能把“没有改变稳定决策”直接等同于“运行更快”。
3. 校准后的恢复计数本身也可能让编译结果变慢。只约束随后的风险投影，不能消除已经在恢复与校准阶段产生的性能下降。

下一项算法工作应对具体内联或布局决定做固定决定的编译对照，估计其耗时与代码大小影响，把这些代价送回目标；并将保护范围延伸到恢复与校准阶段。继续盲目调投影预算或增加重复计时不会解决这三个原因。

## 与老师完整最小论文版本还差什么

本轮完成的是**决策风险模块的可运行最小实现和扩展数据集**。老师第 20 节的完整最小论文版本尚未全部实现：

- 变换来源图已保存，但还没有把内联、克隆、合并、循环变换的频次比例接入观测方程；当前恢复仍使用同阶段已知对应。
- 错误代价目前是静态估计，尚未通过单决策干预实验估计真实耗时损失。
- 基本块频率阈值和局部布局模型还需扩展为更完整的实际消费语义。
- 20 次重采样用于原型，还未完成区间覆盖率和映射不确定性评价。
- 当前全块接口支持普通 C 控制流；异常控制流等 C++ 情况尚未接入完整恢复实验。
- 已建的 40 项语料中，仅开发集 spiff 完成新恢复器接入。其余程序、独立输入以及老师列出的其他大型套件仍需完整评价。

## 复现

```bash
python -m unittest discover -s tests -v
python run_core_risk.py data/node3-seed42-v1 --fresh-calibration \
  --budget 0.01 --output data/new-core-result
python measure_runtime.py data/new-core-result \
  --variants calibrated risk-projected --rounds 15 --seconds 0.3
python audit_core_results.py data/node3-seed42-v1 data/new-core-result
```

多源文件应用接入：

```bash
python prepare_large_experiment.py data/industrial-corpus-v1 \
  --bridge data/core-risk-v4/draper-llvm --program spiff --output data/new-large-flow

python measure_runtime.py data/new-large-core \
  --variants calibrated risk-projected --rounds 15 --seconds 0.3
python audit_core_results.py data/new-large-flow data/new-large-core
```
